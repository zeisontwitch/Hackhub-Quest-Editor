# r167 — Create Wi-Fi exposure and SDK 0.24 feature map

Date: 2026-09-16

## Scope

Turn the r166 in-game Wi-Fi evidence into an author-facing feature, without using the same pass to un-fence unrelated SDK 0.24 surfaces. Also record what actually changed between the pinned `@hotbunny/hackhub-content-sdk@0.21.0` baseline and `0.24.0`, so the next implementation passes can be picked deliberately instead of from patch-note memory.

## What shipped in this pass

- `world.wifi` is no longer in `PALETTE_HIDDEN_TYPES`, so **Create Wi-Fi** appears in the palette and add-node search.
- The Create Wi-Fi inspector keeps the SDK 0.24 fields that r166 tested: SSID, WPA passphrase, signal, BSSID, numeric channel, WPS, router model, router accounts, router ports, devices behind the access point, and cleanup on complete.
- The old blocking hidden-node warning is replaced with an **info** export note: current QA found Bettercap can show no network name after targeting the AP by BSSID, but scanning, joining and cracking still worked.
- The reference-sheet template now includes a real `world.wifi` example, so the node is represented in visible template coverage.
- The handbook has a Create Wi-Fi node page and the node index/front-page counts now say 34 authorable nodes.
- The screenshot plan now includes `node-world-wifi-inspector.png`.
- The dice generator gained two Wi-Fi-specific hardcoded outputs:
  - `bssid` → a locally administered unicast BSSID such as `02:24:xx:xx:xx:xx`;
  - `wifiPassphrase` → a long, copyable WPA-style passphrase.

## Why the Bettercap wart does not block exposure

r166 proved the important player-facing path:

- the AP appears with the expected SSID, BSSID, channel, WPS, signal and RSSI;
- the player can connect and disconnect;
- editor-generated `Network.WifiConnected` / `Network.WifiDisconnected` objectives tick;
- reload does not duplicate the AP;
- Bettercap can still target the BSSID, capture a handshake, and hashcat can recover the password.

The remaining wart is a game display problem: `set wifi.ap <BSSID>` can print `SSID: undefined` for SDK-created APs. It is recorded for SteelWaffe in `docs/03-questions-for-the-developers.md`, but it is not a reason to hide the node.

## SDK 0.21.0 → 0.24.0 declaration diff, grouped by editor opportunity

Generated by comparing `index.d.ts` from `@hotbunny/hackhub-content-sdk@0.21.0` with the pinned `0.24.0` installed in this repo.

### Already usable or implemented

| Area | New in 0.24 | Editor impact |
| --- | --- | --- |
| Wi-Fi creation/control | `Network.createWifiNetwork`, `getWifiNetworks`, `getConnectedWifi`, `connectWifi`, `disconnectWifi`; `WifiNetworkDefinition`; `WifiNetwork` now exposes BSSID, numeric channel, RSSI, WPS and router IP. | Implemented here as the visible **Create Wi-Fi** node. |
| Network cleanup | `Network.destroyNetwork(ip)` now returns `Promise<boolean>` and is documented as always resolving. | Existing cleanup code can keep awaiting it safely; no new node needed. |
| Event catalogue | 99 events instead of 92. New events: `Game.SessionStarted`, `Http.Request`, `Http.Response`, `Http.Intercepted`, `Http.CollaboratorHit`, `Network.WifiDisconnected`, `Terminal.DnsHistory`. | Generic **When event** already exposes them. Dedicated HTTP nodes stay fenced; Wi-Fi disconnected is now usable with Create Wi-Fi. |
| Dice outputs | SDK 0.24 adds user-facing BSSID/channel/WPS fields to Wi-Fi. | Implemented `bssid` and `wifiPassphrase` generators. A channel dice is possible later if number fields learn dice buttons. |

### Good next candidates, but verify before authoring

| Area | New in 0.24 | Candidate editor feature | Risk / gate |
| --- | --- | --- | --- |
| Mail cleanup and replyable mail | `Mail.send()` returns an id, `Mail.remove(id)` exists, and `MailDefinition.replyable` is declared. | Add a cleanup option for sent mail, possibly a **Remove mail** effect, and simplify the replyable-mail path away from the old `Quest.sendMail` workaround. | Needs a focused in-game pass: send id shape, remove-on-complete/unload behavior, and Reply button behavior. |
| Time and Scheduler | New `Time` namespace plus `Scheduler.register`, `schedule`, `scheduleAt`, `cancel`, `cancelKind`, `list`, `remaining`. | New node family: **Schedule story beat**, **On scheduled beat**, or a game-time variant of Wait / delayed mail. | r166 smoke/reload worked, but skipped-time/Wait semantics remain partly untested. Needs careful reload-safe handler design. |
| Tour | New `Tour.start` / `Tour.stop`, quest tour step types and target helpers. | A tutorial/coach-mark node could guide players around apps/pages during a quest. | Depends on localization keys rather than raw copy; should be paired with localization support. |
| Localization | `Localization.register`, `registerAll`, `t`, `language`, `languages`, `onLanguageChange`. | A mod-level translation table and a convention for text fields to use localization keys. | Large product-design pass, not a single node. Text fields, website copy, dialogue and generated code all need a coherent model. |
| Twotter maintenance | `Twotter.updateUser`, `Twotter.removeUser`. | If Twotter is re-enabled, accounts can be patched and cleaned up instead of living forever. | Historical in-game Twotter behavior was unreliable; do not re-enable without a fresh QA scaffold. |
| UI prompt polish | `UI.prompt(options)` options are richer (`title`, `label`, `placeholder`, `defaultValue`). | Improve **Manual input** prompts without a new node. | Low risk after a small in-game check. |
| Desktop app checks | `Desktop.getInstalledApps`, `Desktop.isAppInstalled`. | Conditions or diagnostics around required apps/tools. | Nice-to-have; probably not a story node until a real template needs it. |

### Still fenced or absent

| Area | State in SDK 0.24 | Decision |
| --- | --- | --- |
| HTTP servers/interception/collaborators | Declared and partly green in raw QA, but terminal `curl` is unavailable, DNS-only collaborator lookup failed, and static editor websites did not fire `Http.Request` / `Http.Response` objectives. | Keep HTTP/curl/DNS collaborator authoring fenced until SteelWaffe clarifies semantics or a later build fixes the gaps. |
| Suspicion / log forensics | No `Suspicion` namespace, no suspicion events, no native log-forensics API found in `index.d.ts` or the event catalogue. | Do not ship suspicion nodes. |
| SMS / text messages | No SMS/text-message namespace or event surface found. | Do not ship SMS nodes; keep using other comms channels. |

## Recommended order after this pass

1. **Mail 0.24 QA + cleanup implementation.** This is likely the smallest high-value feature: sent-mail ids and `Mail.remove` can finally solve old quest-mail residue if in-game behavior matches the declaration.
2. **Scheduler design.** Good feature, but it changes the editor's flow model because a scheduled job wakes up later and after reloads; design it once, not as a hidden timer.
3. **HTTP host/proxy design after upstream answers.** Powerful, but `curl`, DNS-only callbacks and static-site event semantics are still not trustworthy enough for author-facing nodes.
4. **Tour/localization as a paired product pass.** Useful for polished content packs, but it needs a text-key workflow, not just a button that calls `Tour.start`.
5. **Twotter recheck only if the user wants social features back.** The 0.24 declarations are better, but historical game behavior says to retest first.
