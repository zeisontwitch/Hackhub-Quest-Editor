Pay the player

Effects  fx.pay

What it does

Pays the player at this point in the story. Use it for rewards, refunds, bounties or contract settlements.

When you'd use it

Put it after the objective or branch that earns the reward. Paying early makes the ending feel already solved.

Add a Notify after it if the player should notice the balance change immediately.

Older saved projects may still carry percentage payout data. New projects use the fixed amount shown here.

In the game, this looks like

The player's bank balance rises, and the transfer appears with the statement label and sender you typed.

Fields

Amount

Credits deposited into the player's bank account.
What to put here
The dollars to award when this node runs.
Example
250
Default
100
Limits
0 or more.
If you leave it empty
A zero payout still runs, but the player receives nothing.

Description

The label on the bank statement line.
What to put here
Write how the client names the job when the transfer appears.
Example
Meridian Capital — contract settlement
Default
"Job payment"
If you leave it empty
The money arrives with no useful label, so the reward looks unexplained.

From IBAN

The sending account, shown in the transfer details.
What to put here
Use this when a client, shell company or agency should appear as the sender.
Example
BG80BNBG96611020345678
If you leave it empty
The game still creates a transfer. Fill it when the sender matters to the fiction.

From name

The sender's name on the statement.
What to put here
Name the sender shown in the transfer details.
Example
Meridian Capital
If you leave it empty
The payment still arrives. Fill it when the player should recognise who paid them.

Wires

SocketDirectionWhat to connect
Ininput Whatever moment earns the money.
Outoutput The closing message, next objective, or follow-up effect after the payment lands.

Then runs next When tests a condition Unlocks opens an objective Data carries a value

A wire only joins two sockets of the same colour, and the editor draws the wire in that colour. That is what the colours are for: match the colours and the connection takes, mismatch them and it will not.

Step by step: add this node to a quest

  1. Find Pay the player under Effects in the palette.
  2. Drag it after the step that deserves a reward.
  3. Set Amount, then write a short statement label.
  4. Fill sender details if the payer matters to the story.
  5. Wire the next beat from Out.

Common mistakes

  • The payment is wired before the win condition. The player gets paid before proving anything. Move it after the objective's On complete socket.
  • No message follows the transfer. The balance changes quietly. Add a notification or closing mail if the reward should land with weight.

Messages you might see

  • Unreachable — nothing leads to this node, so the payment never happens

Related nodes

  • Charge the player — Takes money out of the player's account.
  • Notify — Puts a message on the player's screen.
  • Set quest data — Stores a value for later.
  • Claim another quest — Starts the next quest.
  • Run terminal command — Runs a command in the player's terminal.
  • Open handbook — Opens an in-game article.
