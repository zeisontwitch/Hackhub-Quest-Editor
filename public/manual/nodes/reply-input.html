Manual input

Custom terminal  reply.input

What it does

Adds a command to the player's terminal that waits for them to type an answer, then sends the story down the matching path.

When you'd use it

Use it for a passphrase, a code, or any moment where the player has to know something rather than do something.

Both outcomes need somewhere to go. The player can try again after a miss, so the wrong path is not a dead end unless you make it one.

In the game, this looks like

The player types the command, sees your prompt, and types their answer. The terminal prints your success or failure line.

Fields

Command name

The terminal command the player runs, e.g. decrypt. It appears in help output.
Example
decrypt
Default
"decrypt"

Help text

The one-line description shown next to the command in help.
Example
Decrypt the intercepted payload
Default
"Decrypt the intercepted payload"

Prompt

The text printed before the cursor, e.g. "Passphrase >".
Example
Passphrase >
Default
"Passphrase >"

Mask the input

Hides typing behind * — the player sees “Passphrase > ****” instead of their answer, like a password box. Use it when the answer is a secret.
What to put here
Turn this on to hide what the player types behind asterisks.
Default
off
Limits
On or off.

Match

Exactly equals checks the whole answer. Contains accepts it anywhere in what the player types. Matches pattern is for advanced authors who want to accept a whole family of answers at once.
What to put here
How the answer is checked.
Default
"exact"
Limits
One of the 3 listed below.
Watch out
A pattern match is the hardest of the three for a player to guess at. Use it only when several answers should count.
ChoiceWhat it is stored as
Exactly equalsexact
Containscontains
Matches patternregex

Expected answer

The answer that counts as correct — or the pattern, if you chose “Matches pattern” above.
Default
empty
If you leave it empty
Nothing the player types can be correct, so the story never leaves the wrong path.
Watch out
The player has to be able to find this somewhere. An answer with no clue behind it is a guess, not a puzzle.

Case sensitive

Turn off to accept any capitalisation. Recommended unless case is part of the puzzle.
Default
off
Limits
On or off.
Watch out
Left on, a player who types the right word with the wrong capitals fails. Turn it off unless case is part of the puzzle.

Success message

Printed on a match, then the green “Correct” socket fires.
Example
Decrypted.
Default
"Decrypted."

Failure message

Printed on a miss, then the red “Wrong” socket fires. The player can run the command again.
Default
"Wrong passphrase."

Wires

SocketDirectionWhat to connect
Ininput Whatever should run immediately before the player is asked.
Correctoutput The path that runs when the answer matches.
Wrongoutput The path that runs on a miss. The player can try again, so this is not usually the end.

Then runs next When tests a condition Unlocks opens an objective Data carries a value

A wire only joins two sockets of the same colour, and the editor draws the wire in that colour. That is what the colours are for: match the colours and the connection takes, mismatch them and it will not.

Step by step: add this node to a quest

  1. Find Manual input under Custom terminal in the palette.
  2. Name the command and give it a help line the player will recognise.
  3. Write the prompt, then the answer you expect.
  4. Turn Case sensitive off unless capitalisation matters.
  5. Wire both Correct and Wrong to somewhere.

Common mistakes

  • The answer is nowhere to be found. The player types guesses forever. Put the passphrase somewhere they can reach it.
  • One outcome left unwired. A correct answer that goes nowhere reads as a broken quest. Wire both.

Messages you might see

  • Unreachable — nothing leads to this node, so the command is never registered
