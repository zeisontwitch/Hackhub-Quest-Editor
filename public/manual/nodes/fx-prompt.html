Ask player

Effects  fx.prompt

What it does

Opens a question box, waits for the player to type one line, then sends the story onward. It can accept any answer, check for one expected answer, save what the player typed, or treat closing the box as its own path.

When you'd use it

Use it when the quest needs the player to give a name, code, verdict, passphrase or confirmation outside a terminal command.

Use Manual input instead when the player should type a custom command first. Use Ask player when the question itself should appear at this point in the story.

Save the answer when later mail, notifications or branches need to mention it again. If the answer only chooses the next path, you can leave saving off.

In the game, this looks like

A question box appears over the game. The player types one line and submits it, or closes the box. Password mode hides their typing.

Wires

SocketDirectionWhat to connect
Ininput Whatever should happen right before the question appears.
Submittedoutput The path after a submitted answer. When Accept checks for a specific answer, this is the Correct path.
Wrongoutput The path for a submitted answer that does not match. This socket appears only after Accept checks for a specific answer.
Cancelledoutput The path for closing the question without submitting text.

Then runs next When tests a condition Unlocks opens an objective Data carries a value

A wire only joins two sockets of the same colour, and the editor draws the wire in that colour. That is what the colours are for: match the colours and the connection takes, mismatch them and it will not.

Step by step: add this node to a quest

  1. Find Ask player under Effects in the palette.
  2. Wire it to the story beat that should ask the question.
  3. Write the title and question the player will see.
  4. Decide whether any answer continues, or whether one answer is required.
  5. If later nodes need the answer, fill in Save answer as.
  6. Wire Submitted or Correct onward, and wire Cancelled if closing the box should recover.

Common mistakes

  • The accepted answer is blank. The node is set to check the answer but has nothing to check against. Fill in Answer to accept.
  • The answer is saved under one name and read under another. If the field says recoveryCode, later text must use {{data.recoveryCode}} exactly.
  • Cancelled goes nowhere by accident. If closing the box should remind, punish or retry, wire Cancelled to that follow-up.

Messages you might see

  • Dead end — one of the question's outcomes has no follow-up
  • Unreachable — nothing leads to this node, so the question never appears
