When something goes wrong

Start with the symptom. Every branch ends in something to try.

Start from what you can see, not from what you think you did wrong. Every entry below begins with a symptom and works backwards to a cause.

The two tools that answer most questions are on the top bar. Dry run walks through your quest the way the mod would run it. The Debug probe is a node you drop on the canvas that prints what a node does when it fires — and whether it fires at all. When something does not happen, the probe tells you which half of that sentence is the problem.

Nothing happens at all

Work down this list in order. Each step rules out the most common cause first.

1. Nothing is wired to a start
A node only runs if a wire reaches it from Quest start or On start & reload. Select your first story node and look at its In socket. If nothing is attached, nothing will ever arrive.
2. The node is unreachable
The canvas marks these. A node with an Unreachable badge is on the map but off the story.
3. It is a listener in the wrong place
Anything that has to be listening belongs on On start & reload. Set it up on Quest start instead and it is gone the moment the player reloads.
4. You exported but did not unzip
The game reads a folder in mods/, not an archive. A .zip sitting in that directory is ignored.
5. The quest is not being accepted
Check Start automatically on the Quest tab. With it off, the quest waits for the player to accept it.
Still nothing? Drop a Debug probe straight after the start node and run a dry run. If the probe prints, your start is fine and the problem is further down. If it stays silent, the problem is in that wiring.

The objective never ticks

An objective completes one of two ways: the story flow reaches it, or the event wired to its trigger fires. If neither happens, it stays open forever, and the quest cannot be finished.

Nothing is wired to its trigger
The canvas calls this No trigger, and the quest's Health group counts them. This is the single most common reason a quest cannot be completed.
The wire went into the wrong socket
In takes a blue flow wire and ticks the objective when the story arrives. Trigger takes a cyan one and waits for the player. A wire into In cannot respond to anything the player does.
You wired two events
Only the first event wired to a trigger is used. The second is ignored, so if you added a backup, that is why it did not help.
It is locked behind another objective
The amber Unlocked by socket only accepts a wire from another objective. From anything else it is dropped without a message.

To find out which of these it is, put a Debug probe on the wire feeding the objective and run a dry run. The probe prints whether it fired. A probe that prints and an objective that stays open means the trigger is the problem, not the flow.

The player cannot get into the machine

You built a network and the player cannot reach it. Work through the doors in order.

The router has no way in
The device tree says so in plain words: This router has no way in: set a model for `fern`, or enable support-mail recovery. Neither route is open, so there is nothing to try.
The exploit lands in the wrong account
An SSH exploit lands in a guest account when it finds one. Your files may be in an account the player has not reached yet. Turn the exploit off for a machine that should hold only the accounts you listed.
The address does not exist
If a Place files node points at an address nothing uses, the message is red for a reason: the export drops those files rather than failing. Check the four red messages about addresses in checking your quest.
A port or firewall rule has no machine
Both need a target. With the field blank they act on nothing, and the player sees a machine that behaves like a default one.

The export report

First, the premise: the export does not refuse. The Download .zip button is disabled only while the file is being packed. It produces a .zip whatever the report says, because a quest with problems still deserves to be tested.

What the report is telling you is what will change on the way into the game.

Needs attention
At least one item is an error. Something you built will be dropped or altered. Fix these before you ship.
Good to know
Everything exported as you built it, and what you built may not be what you meant. Read them, then decide.

Each item is quoted in full, with its fix, in the report before you export. Paste the wording into the search box rather than reading the whole list.

A clean report is not a working quest. The report covers what the export can see. It says nothing about whether the puzzle is solvable, which is what dry run and a Debug probe are for.

Frequently asked

I set a payment and the player got nothing
An amount of 0, or a blank field, does nothing at all — the node runs and pays nobody. Type a real number. A hundred dollars is a reasonable first fee.
I paid a percentage and it came out as zero
Percentages are rounded to whole dollars. Ten percent of four dollars is forty cents, which rounds to nothing. Use a fixed amount for small sums.
My files are missing in the game
Almost always an address mismatch. A Place files node aimed at a network your quest does not create has its files dropped by the export, and the field turns red to say so.
The quest panel shows {{data.targetIp}} instead of an address
Tags are filled in when the quest starts. Seeing one raw means the value it names does not exist at that moment — usually because the network that would create it has not run yet.
Can I use two Quest start nodes?
Yes. Every one of them runs. Authors use that for opening threads that do not depend on each other.
My ending never plays
On quest complete runs after a finish path. Add Complete quest to the final beat, or switch on Complete automatically. See how quests finish.
The game does not list my mod
Check that you unzipped it, that the folder is directly inside mods/, and that the folder holds a manifest.json rather than another archive.
Something worked before and now it does not
Undo is unlimited in practice, and the editor keeps a copy in your browser as you work. Before rebuilding anything, try Ctrl+Z.

If none of this matches, open the canvas Debug panel and note the build stamp, then describe the symptom rather than the fix you tried. The build stamp explains where to find it.
