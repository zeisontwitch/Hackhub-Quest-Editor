Pay the player

Effects  fx.pay

What it does

Puts money into the player's bank account.

When you'd use it

Use it when the story pays off. A client wires you a fee after you hand over the file. A employer settles up once the last objective ticks. A refund arrives after the player fixes something they broke.

Most quests pay once, near the end. If the money is the reward for one specific step, wire this node directly after the objective that earns it, so a player who takes a different route does not get paid for work they skipped.

In the game, this looks like

The player's balance goes up by the amount you set. Their bank statement gains one line, reading whatever you typed in Description, sent by whoever you named in From name.

Nothing pops up on screen by default. If you want the player to notice the payment as it lands, add a Notify node beside this one — a balance that changes with nothing on screen gets overlooked.

Fields

Amount

Credits deposited into the player's bank account.
What to put here
A whole number of credits. The fee, the bounty, the settlement.
Example
2500
Default
100
Limits
0 or more. Decimals are not accepted.
If you leave it empty
The payment never happens, and nothing tells you. The exported mod skips the whole transaction when the amount is not above zero — no error, no warning, no line in the bank statement. Check this first when a payment does not arrive.

Description

The label on the bank statement line.
What to put here
The words the player reads on their statement. Write it the way a bank would, because the player reads it as evidence that the job paid out.
Example
Meridian Capital — contract settlement
Default
Job payment
Limits
Any text.
If you leave it empty
The statement line has no label, so the player sees money appear from nowhere.
Watch out
This is a good place for a runtime tag if the amount should read differently per player — see Generate and tags.

From IBAN

The sending account, shown in the transfer details.
What to put here
The account number the money came from. Players who dig into the transfer see it, so it works as a clue.
Example
DE89370400440532013000
Default
empty
Limits
Any text. The editor does not check that it is a real account number.
If you leave it empty
The transfer details show no sending account.
Watch out
The dice button beside this field writes a plausible account number, so you do not have to invent one that looks right.

From name

The sender's name on the statement.
What to put here
Who the player should believe sent the money. A person, a company, or the client's handle from earlier in the story.
Example
Meridian Capital
Default
empty
Limits
Any text.
If you leave it empty
The statement names no sender. Filling in one of From name or From IBAN is enough for the game to attach a sender to the transfer — but a statement with an account number and no name looks unfinished, so fill in both.
Watch out
Keep this consistent with whoever hired the player. A payment from a name the story never mentioned reads as a mistake, not a mystery.
An older kind of payment. If you open a project made before this build, a Pay the player node in it may pay a percentage of the player's balance instead of a fixed sum. Those still work exactly as they were written, and the node shows a note saying so. You cannot set that up on a new node — a percentage is now the job of Charge the player, which takes money out.

Wires

SocketDirectionWhat to connectRequired?If left unconnected
Ininput The node that should run immediately before the payment — usually an Objective or a Branch. Yes The node is unreachable and never runs. The editor flags it — see Unreachable.
Outoutput Whatever should happen after the money lands — a closing line, a Notify, the next objective. No The payment still happens, and the quest stops here. That is the right shape for a final payout.

Step by step: add this node to a quest

  1. Find Pay the player under Effects in the palette on the left.
  2. Drag it onto the canvas, near the node that earns the payment.
  3. Drag a wire from that node's Out socket into this node's In socket. The wire turns the flow colour, which means the two are the same kind of connection.
  4. Select the node and type the amount. 2500 is a reasonable first fee.
  5. Type a statement label — something a bank would print.
  6. Roll the dice beside From IBAN and From name to fill in a believable sender, then edit the name to match your client.
  7. Look at the status bar. It should show no issues for this node. If it says Unreachable, the wire in step 3 did not take.

Common mistakes

  • The amount is 0 or blank, so nothing happens. There is no warning for this. Open the node and check Amount before anything else.
  • The node is not wired in. A payment floating on its own never runs. Wire something into In.
  • The sender is half filled in. An account number with no name, or a name with no account, makes the statement look broken. Fill in both.
  • The player never notices. The balance changes with nothing on screen. Add a Notify if the payment is the payoff of the whole quest.
  • You wanted a percentage. This node pays a fixed sum. Taking a slice of the balance is Charge the player.

Messages you might see

  • Unreachable — nothing leads to this node, so it never runs.

Related nodes

  • Charge the player — takes money out instead, and can take a percentage of the balance.
  • Notify — tells the player the payment landed.
  • Objective — the task the payment rewards. Wire its completion into this node's In.
  • Set quest data — remember how much you paid, so a later quest can refer to it.
