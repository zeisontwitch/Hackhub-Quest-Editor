How do I…

Walkthroughs, each one solving a single thing an author actually wants. One is written; the other fifteen are listed at the bottom as they are planned.

These are not a feature of the editor. They are arrangements other authors have built, written out as steps you can follow. Each one names the nodes it uses, how long it takes, why the arrangement works, and the two or three ways it usually goes wrong. They are drawn from the built-in templates and from how the game's own quests are put together.

Give the player an objective, and make it tick

You'll need
Objective · When event
Takes
About five minutes

The idea

An objective on its own is a line in the player's journal that never ticks. It has no idea what completing it means. The node that knows is When event — it listens to the game, and when the thing you asked about happens, it fires. Wire the two together and the objective finishes itself.

This is the single most common shape in a quest, and the one thing the editor refuses to let you forget: an objective with nothing wired into its Trigger socket is flagged as an error, because the player can never finish the quest.

Steps

  1. Drag an Objective from Objectives onto the canvas.
  2. Select it and fill in Shown to the player — the line that appears in the journal. Write it as an instruction: Download the manifest from the warehouse server.
  3. Give it an Identifier — a short name only other nodes see, like get-manifest. You will not need it here, but later objectives can unlock behind this one.
  4. Drag a When event from Triggers onto the canvas, beside the objective.
  5. Select it and open Game event. Pick the event that means the player did the thing — for a downloaded file over ssh, Terminal.SSH.FileDownload.
  6. Add a condition under Only when so any file download does not count. Set the field to name, the rule to contains, and the value to manifest.
  7. Drag a wire from the When socket on the trigger into the Trigger socket on the objective. This wire is a different colour from a flow wire, because it is a different kind of connection.
  8. Check the status bar. The error should be gone.

Variations

  • Several things must happen first. Add a second When event and wire both into the same Trigger socket. The objective ticks when any one of them fires — so for "do all three", gate them behind each other instead.
  • Hide it until later. Turn on Hidden until unlocked on the objective and wire another objective's Unlocks socket into its Unlocked by socket. It stays out of the journal until then.
  • Run something when it ticks. Wire the objective's On complete socket to whatever should happen next — a payment, a phone call, the next objective.

If it doesn't work

  • The objective still shows an error. The wire went into In instead of Trigger. Delete it and try again — the two sockets are different colours for exactly this reason.
  • It ticks too early, or on the wrong file. The condition is too loose, or missing. Narrow it, or add a second clause.
  • It never ticks even though the player did the thing. The event you picked is not the one the game fires for that action. A file pulled over ssh raises two events, and listening to only one is a common miss — see the objective never ticks.
  • You still can't see why. Drop a Debug probe after the objective and run a dry run. It prints what each node does when it fires — and whether it fires at all — so you can tell if the trigger is even going off.
