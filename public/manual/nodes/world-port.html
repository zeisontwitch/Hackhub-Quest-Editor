Change port

World building  world.port

What it does

Changes one port on one machine: opens it, closes it, adds a new service, or takes one away.

When you'd use it

Use it when the story should change what a machine exposes. A service comes up after the player flips a switch, or a port closes when they are spotted.

Pick the action first. The other fields mean different things depending on it.

In the game, this looks like

The next scan the player runs shows the port in its new state.

Fields

Device IP

A router IP or any device behind it.
Default
empty
Tags work here
Type {{data.something}} to insert a value you saved with Set quest data.

Action

Open makes an existing port reachable. Close blocks it. Add creates a new service; Remove deletes it entirely.

Wires

SocketDirectionWhat to connect
Ininput Whatever should run immediately before this node.

Then runs next When tests a condition Unlocks opens an objective Data carries a value

A wire only joins two sockets of the same colour, and the editor draws the wire in that colour. That is what the colours are for: match the colours and the connection takes, mismatch them and it will not.

Common mistakes

  • The service name does not match the port number. A scan reporting ssh on port 80 tells the player nobody was paying attention. Keep the two consistent.

Messages you might see

  • Unreachable — nothing leads to this node, so the port never changes

Related nodes

  • Create network — Builds the machines the player breaks into.
  • Create Wi-Fi — Creates a wireless target the player can crack and join.
  • Firewall rule — Allows or blocks a port.
  • Register domain — Points a hostname at an address.
  • Create database — Data for the player to dig out.
  • Place files — Drops files on a machine.
  • Tool response — Scripts what a tool reports.
