Create Wi-Fi

World building  world.wifi

What it does

Adds a Wi-Fi access point to the game's world, with a passphrase, signal strength, optional BSSID and optional devices behind it.

When you'd use it

Use it when the player should work through Bettercap and hashcat before reaching a network.

Give the access point a clue trail. The player needs to learn which network to attack and how to recover the passphrase.

Put machines behind the access point when joining the Wi-Fi should open the rest of the job.

In the game, this looks like

The network appears in the Wi-Fi list and Bettercap scan output. The player can capture a handshake, crack the passphrase, join it, and then reach whatever you placed behind the access point.

Fields

Network name (SSID)

The network name shown in the in-game Wi-Fi list.
Example
DOCKNET-5G
Default
"NEIGHBOUR_5Ghz"
If you leave it empty
The access point has no visible name, so the player cannot recognise the right target.

WPA passphrase

The passphrase the player must discover. Make sure some node in your quest reveals it.
Example
forklift-1948
Default
"letmein123"
Watch out
If the player must type or crack this value later, make sure they can earn it first.

Signal strength

The game's Wi-Fi scale: 0 = weakest, 3 = strongest. It also drives how long joining takes.
What to put here
How strong and quick to join the access point should feel.
Default
2
Limits
0 to 3. Whole numbers, in steps of 1.

BSSID

Optional MAC address shown for the access point. Leave blank to let the game pick one.
Example
02:24:00:00:17:48
If you leave it empty
The game picks one for you. Fill it only when a clue or test needs a fixed value.
Watch out
Current game builds may show no network name after Bettercap targets this value, but the attack still works.

Channel

Optional 2.4 GHz or 5 GHz channel shown by scans. Leave blank to let the game pick one for the SSID's band.
Example
44
Limits
1 to 196. Whole numbers, in steps of 1.
If you leave it empty
The game chooses a channel that fits the network name.

Advertises WPS

Whether Wi-Fi scans show WPS for this access point. Leave off unless your story needs to pin it.
What to put here
Turn it on for targets that should look old, consumer-grade, or poorly locked down.
Limits
On or off.

Router model

Enables the in-game `fern` recovery route. Leave blank to disable it.
Example
TP-Link Archer C6
If you leave it empty
The access point still exists. Leave this blank if router-model recovery is not part of the puzzle.

Router accounts

Accounts on the access point's own system. Their files land in /home/<username>/.
What to put here
Accounts on the access point's own router. Use them for an admin-panel step, not for the machine behind it.
Default
an empty list

The button reads Add account.

Username

The login name for ssh, ftp or a web login page.
Example
admin

Password

Leave blank to let the game pick one.
Example
forklift-1948
Default
"letmein123"
Watch out
If the player must type or crack this value later, make sure they can earn it first.

First name

Shown on the account's profile page and in whois results.

Last name

Shown on the account's profile page and in whois results.

E-mail

The account's e-mail address. Useful as a lead the player can mail.
Example
admin@docknet.internal

Accepts reverse TCP

Lets the player open a connection from this account back to their own machine. Turn on only if your quest needs it.
Limits
On or off.

Router ports

Open ports on the access point itself.
What to put here
Services exposed by the access point's router itself.
Default
an empty list

The button reads Add port.

External port

The port number as seen from outside. This is what nmap reports and what the player connects to.
Example
80
Limits
0 to 65535.

Internal port

The port the service actually listens on inside the machine. Leave equal to the external port unless you are deliberately redirecting.
Limits
0 to 65535.

Service

What nmap prints next to the port, e.g. http, ssh, ftp, mysql. Free text — it is a label, not a real service.
Example
http

Version

The banner nmap -sV prints. Use three numbers and no letters — metasploit refuses "7.2" and "7.2p2", leaving the player unable to run the exploit. Blank omits the version line.
Example
nginx 8.4.71

Open

Closed ports show as filtered to nmap.
Limits
On or off.

Devices behind the access point

Machines reachable through this access point. Add a router here to build a second network hop.
What to put here
The machines the player reaches after joining the Wi-Fi.
Default
an empty list

Also remove this access point when the quest is completed

Off by default: the access point stays in the world after the quest. Abandoning the quest removes it either way.
What to put here
Turn this on for a temporary access point that should disappear when the job is done.
Default
off
Limits
On or off.

Wires

SocketDirectionWhat to connect
Ininput Whatever should happen before the access point exists.
Outoutput The briefing, objective, or next setup step that assumes the access point is live.

Then runs next When tests a condition Unlocks opens an objective Data carries a value

A wire only joins two sockets of the same colour, and the editor draws the wire in that colour. That is what the colours are for: match the colours and the connection takes, mismatch them and it will not.

Step by step: add this node to a quest

  1. Find Create Wi-Fi under World building in the palette.
  2. Name the network and set the passphrase the player has to recover.
  3. Leave BSSID and Channel blank unless your clue needs a fixed value.
  4. Add router ports or accounts only if the access point itself should be a target.
  5. Add machines under Devices behind the access point when joining Wi-Fi should unlock more systems.

Common mistakes

  • No passphrase trail. The player can see the access point and has no fair way to join it. Hide the passphrase, the model, or the handshake route somewhere in the quest.
  • Putting the prize on the router by accident. Router accounts and ports are for the access point itself. Put the company server under Devices behind the access point.
  • Treating the Bettercap name display as failure. If targeting by BSSID shows no name, keep going: the current game build still captures and cracks the handshake.

Messages you might see

  • Unreachable — nothing leads to this node, so the access point is never created
