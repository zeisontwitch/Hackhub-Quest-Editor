On start & reload

Quest lifecycle  entry.load

What it does

Runs when the quest is claimed, and again every time the game loads it. Anything that has to be true in every session goes here.

When you'd use it

Put anything that watches for a player action here rather than in Quest start. A watcher armed once stops working after the player reloads.

Use it for the pieces a returning player expects to still be working: the listeners behind your triggers, the state of a machine they left mid-job.

Keep one-off story beats out of it. They belong in Quest start, or the player sees them again on every load.

In the game, this looks like

The player loads a save with your quest in progress and this fires again, before they touch anything.

Fields

This node has nothing to configure. It marks a moment in the story and runs whatever is wired after it.

Wires

SocketDirectionWhat to connect
Outoutput Whatever should happen after this node runs.

Then runs next When tests a condition Unlocks opens an objective Data carries a value

A wire only joins two sockets of the same colour, and the editor draws the wire in that colour. That is what the colours are for: match the colours and the connection takes, mismatch them and it will not.

Step by step: add this node to a quest

  1. Find On start & reload under Quest lifecycle in the palette.
  2. Drag it onto the canvas.
  3. Wire the nodes that have to be re-armed each session to its Out socket.

Common mistakes

  • A one-off story beat is wired here. This runs on every load, so the player meets the opening again. Move it to Quest start.
  • Nothing is wired to Out. The node runs and does nothing. Delete it, or wire something to it.

Messages you might see

  • Empty — nothing is wired to Out, so the node does nothing

Related nodes

  • Quest start — Runs once, when the quest is claimed.
  • On quest complete — Runs after the quest is completed.
  • On quest abandoned — Runs if the player gives up.
