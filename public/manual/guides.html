Feature guides

One page per surface — how to get there, and what to do once you are.

One page per surface of the editor, in the order you meet them. Each section says what the thing is for, what is on it, and what goes wrong when you ignore it. Where a setting has a consequence you cannot see, the consequence is stated.

The inspector's three tabs

The panel on the right holds three tabs, and one of them is disabled until you need it.

Node
Every field on the node you have selected. Greyed out when nothing is selected, because there is nothing to show.
Quest
Settings for the quest you are looking at. This is the default tab, so it is what you see on an empty canvas.
Mod
Settings for the whole file: the name on the box, the version, the icon.

The panel can also leave the side of the window. Drag its left edge outward and it floats, which helps when a node sits underneath it. Drag the title bar to move it and the bottom-right corner to resize it.

The floating panel and the docked one are the same inspector. The fields are identical either way, so nothing is hidden in one mode. The editor also keeps the floating panel inside the window, so you cannot lose it past an edge.

Quest settings

Five groups, thirteen settings. Most quests need four of them.

Identity

Quest identifier
Internal. Unique across your mod, and the thing other quests name when they start this one.
Display title
What the player sees in their quest list.
Description
The pitch, shown before they accept. This is also the only place to say which addons your quest needs.
Journal group
Folders the player's journal into groups. Two quests in the same group read as one story.

Rewards

Money and XP, both plain numbers. These are what the game pays for finishing the quest, which is separate from anything a Pay the player node does mid-story.

Behaviour

Start automatically
The quest begins on its own instead of waiting to be accepted.
Complete automatically
The game closes the quest once its objectives are done. Leave it off when a Complete quest node decides the ending. See how quests finish.
Player can abandon
Lets them give up. Turning it off also means On quest abandoned never runs.
Show a manual complete button
Puts a button in the player's hands and lets them decide when the quest is over.
Tidy the objective list when the story ends
Clears completed objectives so the panel is not a scroll of old text.
Closing line
One sentence shown when the quest ends. Use it with the legacy tidy-up option, or as the final visible line before a Complete quest node.

Employer

First name, Last name and E-mail. The person the quest is from. Worth filling in, because a job with no name behind it reads as a system message.

Health

Not a setting. This group reads your quest back to you: how many objectives it has, and how many of them nothing can ever complete. It is the fastest check in the editor.

Mod settings

These describe the file, not the story. Everything here ends up on the card the game shows the player.

Mod id
Internal, and part of the exported file's name. Changing it later makes the game treat the result as a different mod.
Display name
The name on the box.
Version
Also part of the filename, which is how two builds of one mod avoid overwriting each other.
Author
Your name. Defaults to the editor's name if you leave it.
Description
The blurb in the mod list.
Cover image
and Icon — the two pictures. Both optional, both shipped inside the .zip.
Tags
Search terms for the mod list.

Dialogues

The Dialogues button opens the phone conversations, in one place rather than scattered across the canvas. This is where you write who says what, in what order, and with what delay.

A conversation needs something to reach it. Nothing wiring into a Dialogue node is a problem the export report will raise, because a conversation nobody triggers is a conversation the player never sees.

Websites

The Websites button opens the builder: your sites on the left, and the pages of whichever site you picked on the right. A site is a host; a page is a path on it.

Each page has a live preview beside the editor, so you see roughly what the player will see.

A host belongs to the whole game. Two mods claiming one domain collide, and the export report says so. A page can also be unlisted, which means only a direct address or a brute-force tool finds it. That is deliberate when you want a page hidden, and a mistake when you do not.

Templates

Thirteen starter projects, from a blank canvas to a 36-node quest, each with a difficulty and a node count. The window also imports a project file somebody else saved, which is how quests get shared.

Loading a template replaces what is on the canvas. That is why the editor offers Save current quest first before clearing anything.

Two of the thirteen are not quests at all. Node Reference holds one of every node with example input, and Quest Cookbook collects common patterns. Neither is meant to ship — open them to read how something is done, then copy it into your own project.

Dry run

The Dry run button walks through your quest the way the exported mod would run it, without installing anything. It is the closest thing to a test drive the editor has.

Watch the order rather than the outcome. If a node you expected never appears, nothing is wired to reach it. Drop a Debug probe after it and run again: the probe prints what a node does when it fires, and whether it fires at all.

Dry run is not the game. It runs your logic, not the game's tools. A conversation, a scan or an exploit can still behave differently in the real thing, which is why the timed-conversation warning tells you to check in-game before you ship.

Addons

Addons are packs made by other people that add events and tool actions to your editor. The window's own description of them:

Community addons drop in here as data: their events join the trigger picker, their quest data becomes nodes. Addons are data only — the editor never runs code from them.

Once a pack is loaded, its events show up in the trigger picker under Community addons, and its tool actions appear in the palette under the same name. Nothing changes until you load one.

Your players need the pack too. A quest built on an addon does nothing for anyone without it, and the game will not tell them what is missing. Name the pack in your quest description — the editor warns you about this on the node, but it cannot write the description for you.

Settings

The Settings button holds editor preferences. None of them reach your quest or the exported mod; they change how the editor looks and feels for you.

Canvas
Show grid, Grid colour, Grid opacity, Grid scale and Snap to grid.
Wires
Animated wires, Springy wires, Line weight and Mark size.
Appearance
Interface font, with a Follow the editor theme option for the grid.
Getting out
Clear the autosaved draft and Reset all editor preferences. Both are deliberate and both ask first.

Canvas tools

Top left of the canvas. These move nodes around; none of them change what your quest does.

Tidy up
Arranges the whole graph left to right, by how far each node sits from its entry point. The one to reach for after a long building session.
Align in a row · Align in a column
Puts the selected nodes on one line, centred.
Space out across · Space out down
Equalises the gaps without moving anything onto a line. The outermost nodes stay where they are.
Springy wires
Switches the wires between settling and drifting. Purely cosmetic, and off is calmer on a big map.
Debug
Opens the editor's own diagnostics: the build stamp, wire numbers, counters and a recent-event log. This is not the Debug probe node — that one goes on your canvas and prints what a node does at runtime.

Beside the tools is the counter described in where messages appear. It reads No issues when the quest is clean.

Things outside your quests

Every other part of this handbook is about a quest. This section is about the four things a pack can put outside a quest — a start-menu entry, a small box on the desktop, entries in a right-click menu, and the words your pack can speak in another language.

They all live in one window, opened from Pack extras on the toolbar. Nothing there is required: a pack with none of it exports exactly as it always did.

A start-menu entry

The start menu has a strip of entries along the bottom. A pack can add one, with a picture and four possible jobs: say something, start one of your quests, send the player a letter, or open the game's own handbook.

Picture
Optional, and worth having for a pack whose entry sits beside the game's own. Pick a picture from your machine: it travels inside the pack, so keep it small — the menu draws it the size of a letter in this sentence.
The entry's own words
The label, and the sentence a "say something" entry shows. Both take translated words (see below).
When it appears
As soon as the player's game loads your pack. Nothing has to be started for it to sit there.
Positions are the game's. Entries land in the bottom strip. An earlier version of the game ignored a "top" or "bottom" choice, so this editor does not offer one.

A box on the desktop

A widget is a small web page the game draws on the player's desktop: a note, a counter, a status board — anything you can build with the same editor the website builder uses, including the preview.

Size and place
Width, height and the corner it sits at, in the desktop's own pixels.
See-through
Off by default, so a widget arrives with a background. Turn it on for a widget meant to look painted onto the wallpaper.
A widget's own words are a page, not a quest. What you type inside the widget is shown as you typed it: translated words do not reach in there, because the widget is a file the game opens, not a line of text it fills in. Write those words in the language you want them in.

An entry in a right-click menu

Where a player right-clicks, a pack can add an entry: on a file, on the desktop, on the taskbar, or on a window. Each entry carries a label, an optional picture, and one of the four jobs above.

Use it for the thing a player reaches for while looking at something — "inspect this file", "send this to my notes", "open the walkthrough".

The same words in another language

The language table is a grid: one row per line of text, one column per language you have written it in. The game ships with the languages a player can choose, and this editor offers exactly those.

A line you add is used with a token that looks like this:

{{tr.name.of.your.line}}

Paste that token wherever a text field takes your words — a quest title, a mail's subject, a menu label, a notification. When the game shows it, it looks up the line in the player's language, falls back to English when that language has no line yet, and shows the token itself if the line is missing altogether.

The game reads some words once, at load. A quest's title, and the labels on a menu entry, are taken by the game while your pack loads. Whatever language the player had chosen for that save is the language those words stay in until the next load — which is also why changing the game's language mid-session does not change them, and why switching language and loading a save does.

The handbook entry, honestly

One of the four jobs opens the game's handbook. In the game as it stands, it opens the handbook on that book's own front page: there is no way, yet, to send a player to a named page inside it. The entry is still worth having for "here is the book", and the editor's log file records what was asked for. See When something goes wrong for reading the log.

Two buttons beside a text field

Some text fields carry one or two small buttons. They look alike and do opposite things, which is worth getting straight early.

The dice
Fills the field with a realistic value it makes up — a plausible address, a named contractor, an e-mail. The result is fixed forever, because it is now text you typed.
The sparkle
Inserts a tag the game fills in when the quest runs, like the address the game allocates to your network. The value is different every playthrough, because it does not exist yet.

Roll the dice when you want something concrete to look at while you build. Use the sparkle when the game is the only thing that knows the answer — a machine address is the common case, since the game allocates it.

Both are ordinary edits. Either one can be undone with Ctrl+Z, exactly like typing.
