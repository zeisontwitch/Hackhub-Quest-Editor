Debug probe

Flow control  flow.debug

What it does

Prints what the quest is doing at this point, so you can see whether a node runs and what it carries.

When you'd use it

Drop one anywhere the story seems to stop. If it prints, the story got that far. If it stays silent, look upstream.

Turn on Show on screen too while you test, so you do not have to open the log file.

In the game, this looks like

Nothing appears on screen unless you ask for it. The probe writes to the game's log.

Wires

SocketDirectionWhat to connect
Ininput Whatever should run immediately before this node.
Outoutput Whatever should happen after this node runs.

Then runs next When tests a condition Unlocks opens an objective Data carries a value

A wire only joins two sockets of the same colour, and the editor draws the wire in that colour. That is what the colours are for: match the colours and the connection takes, mismatch them and it will not.

Step by step: add this node to a quest

  1. Find Debug probe under Flow control in the palette.
  2. Drop it on the wire you suspect, between the two nodes in question.
  3. Turn on Show on screen too if you would rather not open the log.
  4. Run the quest. A printed label means the story reached that point; silence means it did not.

Common mistakes

  • The probe is left on in a shipped quest. The player reads your debugging notes. Turn Show on screen too off before you export.

Messages you might see

  • Unreachable — nothing leads to this node, so the probe never prints

Related nodes

  • Branch — Sends the story down one of two paths.
  • Wait — Pauses the story.
  • Timer — Fires the next node at a later in-game time — a delay, a clock time N in-game days from now, or a fixed in-game date.
  • Reroute — A tidy point for your wires.
  • Random pick — Picks one path at random.
  • Sequence — Fires several outputs in order.
