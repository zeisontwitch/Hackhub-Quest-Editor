## Implemented in this pass

1. **SDK pin and catalogue refresh**
   - `package.json` and `package-lock.json` now pin the SDK to exactly `0.24.0`.
   - `reference/generate-event-catalogue.mjs` handles SDK 0.24 declarations: generic interfaces, named aliases, inline docs, HTTP grouping, `Game.SessionStarted`, and hard failures for unresolved named payloads or unclassified events.
   - `reference/hackhub-events.json` now reports 99 events.

2. **Event model and picker fixes**
   - Added SDK 0.24 events:
     - `Game.SessionStarted`
     - `Http.CollaboratorHit`
     - `Http.Intercepted`
     - `Http.Request`
     - `Http.Response`
     - `Network.WifiDisconnected`
     - `Terminal.DnsHistory`
   - Removed events: none.
   - Updated event group copy so HTTP lives with browser/web events.
   - Updated event docs for renamed and corrected payload fields, including `Browser.WebsiteOpened.Url`, `RemoteConnection.*.targetIp`, primitive `Terminal.Lynx.Search`, primitive `Terminal.Geoip`, primitive `Terminal.FTP.Connect`, and null/undefined no-payload events.

3. **Primitive event handling**
   - `PAYLOAD_IS_REALLY_PRIMITIVE` is now empty because SDK 0.24 correctly declares the previous Lynx mismatch as `string`.
   - `isPrimitivePayload()` now only treats bare `string`, `number`, and `boolean` as matchable primitive payloads, not `undefined` or `null`.
   - The runtime remains backward-compatible: old projects that saved fields such as `query` still match a bare primitive payload.
   - The simulator now probes primitive events through `isPrimitivePayload()`.

4. **Template field fixes for SDK 0.24 declarations**
   - `Browser.WebsiteOpened` template conditions now use `Url` instead of `url`.
   - `RemoteConnection.Established` conditions now use `targetIp` instead of `ip`.

5. **Wi-Fi status update without lifting the palette fence**
   - SDK 0.24 declares `Network.createWifiNetwork()`, `getWifiNetworks()`, `getConnectedWifi()`, `connectWifi()`, and `disconnectWifi()`.
   - `world.wifi` stays hidden from the palette until an in-game QA pass verifies the full authored shape.
   - Legacy projects that already contain a `world.wifi` node now pass the existing authored router data into the native SDK 0.24 creator when present: SSID, password, signal, BSSID, channel, IP, model, users, ports, and children.
   - The older router-network fallback is kept for older game builds.

6. **Manual refresh**
   - Handbook build stamps were moved to `2026-09-16.r165`.
   - The appendix event list now renders all 99 SDK events.
   - `docs/manual/inventory.json` reports SDK `0.24.0`, 34 node types / 33 obtainable, 120 editable fields, 65 sockets, and 99 events.
   - `world.wifi` remains excluded from manual node pages because it remains hidden.

## Verified fixed by SDK declarations and tests

These are safe to update in editor metadata/tests because the pinned SDK declarations now agree:

- The `Terminal.Lynx.Search` mismatch is fixed at the declaration level: the payload is `string`.
- `RemoteConnection.Established` and `RemoteConnection.Disconnected` now expose `targetIp`, `targetPort`, `fromIp`, `user`, and `t`.
- `Terminal.DnsHistory` is now declared.
- `Network.WifiDisconnected` is now declared and carries no payload.
- HTTP/curl-related events are now declared.
- Wi-Fi creation is now declared, so the old “SDK has no wireless creator” wording was replaced.
- Scripted command data replacement is expected to be fixed in-game per patch notes, but the editor still keeps its harmless remove-before-add behaviour.

## Not lifted yet

These remain fenced because `docs/07` requires in-game verification, not patch notes alone:

1. **Quest completion workaround**
   - SDK 0.24 declares `this.complete()`, `this.retire()`, and `Quest.unclaim()`.
   - The editor still defaults `autoComplete` to `false` and still avoids relying on automatic quest completion.
   - Required next pass: export a minimal quest that calls the new completion route, verify no renderer freeze, verify `OnComplete`, rewards/history/list cleanup, and verify a reload after completion.

2. **`world.wifi` palette/manual page**
   - SDK 0.24 declares Wi-Fi creation and management.
   - The node remains hidden until in-game QA confirms Wi-Fi list visibility, bettercap scan output, password cracking/joining, signal/channel/WPS behavior, devices behind the AP, cleanup, reload behavior, and old-game fallback behavior.

3. **Twotter authoring**
   - SDK 0.24 declares repair/removal APIs, and patch notes say Twotter-breaking content-pack saves are repaired.
   - The editor still has no Twotter node re-enabled in this pass.
   - Required next pass: verify account create/update/remove in-game, search behavior after mod uninstall/reload, and cleanup in `OnModPackageUnloaded`.

4. **Replyable mail and scripted outgoing mail**
   - SDK 0.24 declarations should be checked in detail before changing the current Mail.send / Quest.sendMail fallback.
   - Patch notes explicitly fix a Reply-button bug, but docs/07 says scripted outgoing mail was not fixed in that response. Do not replace the current workaround without a focused in-game test.

5. **Scheduler / in-game clock integration**
   - SDK 0.24 declares `Time` and `Scheduler` APIs.
   - Existing `flow.delay` remains a short real-time wait node.
   - Candidate new work: add a “schedule on game clock” effect/node or a delayed mail/message mode backed by `Scheduler`, not by browser timers.

6. **HTTP server / curl support**
   - SDK 0.24 declares `Http.registerHost`, route helpers, history, collaborators, interception, and `Http.fetch`.
   - Existing website support still uses Website classes.
   - Candidate new work: design an HTTP route/server node family and/or curl/scripted-response support after confirming how the in-game browser and `curl` choose between Website classes and the new Http namespace.
