On quest complete

Quest lifecycle  entry.complete

What it does

Runs when the quest is marked complete. Under the default settings, that never happens.

When you'd use it

By default a quest has no way to complete. The player gets no Complete button, and auto-complete is off.

So end your story from the last objective's On complete socket instead. That path always runs when the objective ticks over.

Keep this node for the day you switch on auto-complete or add a completion button. Until then it sits there doing nothing.

In the game, this looks like

Under the default settings the player never sees the result of this node, because the quest never reaches the state that fires it.

Fields

This node has nothing to configure. It marks a moment in the story and runs whatever is wired after it.

Wires

SocketDirectionWhat to connect
Outoutput Whatever should happen after this node runs.

Then runs next When tests a condition Unlocks opens an objective Data carries a value

A wire only joins two sockets of the same colour, and the editor draws the wire in that colour. That is what the colours are for: match the colours and the connection takes, mismatch them and it will not.

Step by step: add this node to a quest

  1. Decide first whether your quest can complete at all. If it cannot, wire your ending to the last objective instead.
  2. If you have switched on completion, find On quest complete under Quest lifecycle.
  3. Wire the closing beats of your story to its Out socket.

Common mistakes

  • The ending of the quest is wired here. The player finishes every objective and sees nothing, because the quest never completes. Wire the ending to the last objective's On complete instead.

Messages you might see

  • Only runs on completion — the editor warns you this node will never fire under the default settings

Related nodes

  • Quest start — Runs once, when the quest is claimed.
  • On start & reload — Runs on claim, and again on every load.
  • On quest abandoned — Runs if the player gives up.
