# r174 (plan + record): the r172/r173 audit

## Why this round

Zeis asked for a read-back audit of the two most recent rounds — r172
("Schedule beat", the first `Time`/`Scheduler` exposure) and r173 (the
rename to "Timer", the "beat" purge, and the `daytime`/`at` calendar modes)
— after the r173 coding pass left issues behind (it also truncated
`runtimeSource.ts` mid-edit and repaired it before finishing).

Two constraints shaped the method:

- **Git history here is squashed.** `HEAD` is a single root commit and
  `origin/main` (`5da8f57`) is an unrelated r148-era snapshot, with no tags
  and no releases — there is no r172→r173 diff to read. The audit therefore
  runs on the code, the round plans, the committed artifacts, and tests that
  are proven to fail when a guard is reverted.
- **The plans are the specification.** r172 and r173 both wrote down what
  should exist (fields, formulas, warning copy, counts, tests, QA rows);
  the audit grades the shipped state against those documents.

## What was checked

- **Schema/registry:** `TimerNodeDataSchema`, the node union, the registry
  entry (label, blurb, `mode` select, the seven new fields, `showWhen`
  behaviour, `create`).
- **Analysis:** the two warnings and their new shapes (`Nothing scheduled`

- **Runtime (`runtimeSource.ts`):** `computeTimerFireAt` (clamping; the

  `Scheduler.list`, re-arm ≤ 20 for not-live quests, cancellation on
  complete/abandon, and the renamed console lines; file integrity
  (2,712 lines, coherent tail — the r173 truncation left no residue).
- **Dry run:** the `scheduleAt` stub and the `Timer …` log strings.
- **"Beat" purge:** every remaining `beat` in `src/` classified as either the
  separate **Story beat** node (untouched, correctly), internal identifiers
  (`BEAT_KIND`, `liveBeats`, `beatJobs`, `armBeat`… — developer-facing, logs
  renamed), or generic prose.
- **Artifacts/docs:** `docs/manual/node-voice.json`, the generated manual
  (page, `checking.html` anchors, `search-index.js`, shot list), the QA
  project and scaffold test, README/HANDOFF rows, `docs/06`, inventory

  `parseProjectFile` and `loadDraft`'s path.

`npm test` 1,584 passed / 80 files, `npm run build` succeeds (only the

## Defects found and fixed

### 1. The rename shipped without a migration (data loss)

r173 moved the persisted type id `flow.schedule` → `flow.timer` on the
premise that "r172 was never played in game, so no user content depends on
the old id". That is true of **mods**, not of **project documents**: an r172
draft in `localStorage` or a `.quest-editor.json` kept by an author still
names the old id, and `ProjectSchema` is a discriminated union with no
legacy alias.

Measured, not assumed: a minimal r172-shaped project fails
`parseProjectFile` with
`Not a quest project — problem at “quests.0.graph.nodes.0.type”.`, and
`loadDraft` discards a draft that fails validation — so the whole document
is lost, silently but for a console warning. Every previous node-type change
in this project ships with a `migrate.ts` case (`comms.*`, `fx.pay`), and
`share.ts`'s comment states the rule: a project saved before a type changed
must still open.

**Fix:** `case "flow.schedule"` in `mapNode` returns the node with
`type: "flow.timer"`. The delay fields (`days`/`hours`/`minutes`) are
unchanged, and r173's `mode`/calendar fields take their schema defaults.
Four regression tests in `migrate.test.ts` cover the shape, validation, the
end-to-end import, and the no-op case. Falsified: deleting the case fails
three of them.

### 2. `public/manual/search-index.js` was stale, and nothing guarded it

The committed index — the manual's search data — still carried
`documents editor build 2026-09-17.r172` in five entries while every page
said r173, because the index is generated (`npm run gen:manual`) and the
manual gate (G15) only walks `.html` pages. Search results therefore quoted
pre-rename text and an old stamp.

**Fix:** regenerated (255 entries / 49 pages); a second G15 test now fails on
any `build …` stamp in the index that is not `EDITOR_BUILD`. Falsified:
re-stamping the index with r172 fails it with "quotes 5 stale build stamp(s)".

### 3. The r173 plan's promised guard test was missing

D1 of the r173 plan required "the registry label is exactly `"Timer"`",
with a falsification step ("revert the label → the label test fails"). No
such test existed — `"Timer"` appeared in `src/` only at the registry entry
itself. **Fix:** `schema.test.ts` gains the check inside the registry
suite; falsified by reverting the label.

### 4. Small residue

- The QA quest's mail sender was still `qe24-beats@test.net` — a
  player-visible string the round's purged wording otherwise missed. Now
  `qe24-timer@test.net`.
- `docs/06-how-it-works-today.md` still said "current as of r171" with
  1,561 tests / 38 node types. Refreshed to r174 / 1,590 / 39.

## Verified conforming (no change)

- All three modes, their fields and `showWhen` gates, the runtime formulas,
  fail-open policy, arming/idempotency/cancellation, the dry-run stub and
  log strings, the warning copy and its severities, the manual page and

  (`BEAT_KIND` and friends); every player-visible string says "timer".

## Left for a decision (reported, not changed)

1. **No refreshed installable QA export.** `reference/sdk-0.24-qa/editor-export/`
   is still the r166 artifact (its README says so; quests: `QESdk024EditorQa`
   only), while the QA project now carries `QESdk024TimerQa`. r172's S-01
   says "Install the refreshed QA export"; nothing in the repo matches that.
   Either export from the editor and commit it, or state the route in the QA
   README.
2. **Manual-generator wording for conditional fields.** "Only once *When it
   fires* is set. Until then the field is hidden." is inaccurate for fields
   gated on a select that has a default (`mode` defaults to `after`, so the
   delay fields are visible immediately). Pre-existing across every
   conditional field (Pay's `amountMode` too) — a generator change, not a
   Timer fix.
3. **S-04 still decides the `at` timezone.** The `at` arm assumes the in-game
   clock shows the player machine's local zone; the ISO+raw `fireAt` log is
   the probe. Unchanged, and documented in the code and the plan.
