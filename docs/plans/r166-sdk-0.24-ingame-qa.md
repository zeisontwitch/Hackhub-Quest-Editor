### What is "intercept"?

Intercept is the new SDK 0.24 proxy-style HTTP hold switch. When it is on, the game can pause a browser/`curl` request, emit `Http.Intercepted`, and wait for a tool to forward or drop that request. It is useful for future proxy/Burp-like nodes, but it is a footgun if left on.

Use two terminal windows because the Browser or terminal running `curl` may wait until another terminal forwards the request:

```text
# Terminal A
qe24 intercept on
# Open http://qe24-http.test/ in the in-game Browser, or, if curl exists:
curl http://qe24-http.test/

# Terminal B
qe24 intercept queue
qe24 intercept forward  # forwards and turns intercept off in the current harness
qe24 intercept off      # optional cleanup/safe no-op
```

Expected: `http-intercepted` ticks, `qe24 intercept queue` shows one held `GET`, and the waiting Browser/`curl` request prints the page after `forward`. A blank/dark page while intercept is on means the request is probably held. If anything seems stuck, run `qe24 intercept off` in another terminal. If two terminals are inconvenient, or if the terminal says `curl` is not found and the Browser fallback is not practical, skip this row and mark it `Blocked`.

### What changed in SDK 0.24 that this checks?

- HTTP/browser/curl event surface: `Http.Request`, `Http.Response`, `Http.Intercepted`, and `Http.CollaboratorHit`.
- Native Wi-Fi creation: BSSID/channel/WPS plus connection/disconnection payloads.
- Time/Scheduler APIs: jobs scheduled on game time and Wait/save-load behavior.
- Quest lifecycle APIs/fixes: `this.complete()`, `this.retire()`, `Quest.unclaim()`, final-objective freeze and abandoned-quest cleanup.
