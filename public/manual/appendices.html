Glossary and limits

Look-ups: every word, every key, and everything this editor cannot do yet.

Reference material: the words, the keys, the limits, and the full list of events. Nothing here needs reading in order.

Glossary

Node
One card on the canvas. Each does one thing: send a message, build a machine, pay the player.
Wire
The line joining two nodes. Wires decide what runs and in what order; where the nodes sit decides nothing.
Socket
The point a wire attaches to. Every socket takes one kind of wire and refuses the others.
Palette
The list of nodes down the left. Drag one out, or click it to drop one in the middle.
Inspector
The panel on the right, with its Node, Quest and Mod tabs.
Field
One setting on a node. Every field is a dropdown, a switch, a box to type in or a colour.
Hint
The grey sentence under a field. It is the editor's own wording, and this handbook quotes it rather than paraphrasing.
Message
Something the editor has found wrong. Amber is unfinished, red is broken. All of them are in checking your quest.
Project file
Your editable work. Saved with Save, reopened with Load. This is the only thing you can carry on editing.
Mod, or the .zip
Finished output for the game. Not editable. Exporting makes a new one every time.
Export
Turning a project into a mod. The editor calls the button Export mod.
Dry run
Walking through your quest the way the mod would run it, without installing anything.
Debug probe
A node you drop on the canvas that prints what a node does when it fires. Not the same as the canvas Debug button.
Objective
A line in the player's quest panel. The only part of your quest they are told about.
Event
Something the player does in the game, which your quest can hear. There are 99.
Trigger
Only ever a socket: the cyan one on an objective. The node that feeds it is a When event.
Tag
Text in braces that the game fills in when the quest runs, like a machine address it allocates. The sparkle button inserts one.
Addon
A pack made by somebody else that adds events and tool actions to your editor. Data only.
Drawing aid
A node that does not run: a Sticky note, a Story Beat or a Group frame. A frame's name and comment still ship as comments.

What this editor cannot do yet

Stated plainly, because each of these has cost somebody an afternoon. None is a bug; each is a boundary, and the editor does not always tell you when you cross one.

It cannot give an objective two triggers
Only the first event wired to a trigger is used. A second one is ignored without a message. If you need two ways to finish, use two objectives.
It will not finish a quest without a finish path
Add Complete quest to a success ending, or switch on Complete automatically. On quest complete runs after that path.
It cannot fix Bettercap's access-point name display
Create Wi-Fi now ships as a real access point. In the current game build, Bettercap may show no network name after you target a mod-created access point by BSSID, but scanning, joining and cracking still work.
It cannot stop you exporting a broken quest
The report describes consequences; it gates nothing. A .zip always downloads. That is deliberate, but it means a downloaded file is not proof of a working quest.
It cannot tell your players they need an addon
A quest built on an addon does nothing for anyone without it, and the game says nothing. The quest description is the only channel, and you have to write it.
It cannot keep a live conversation interactive
Turn on Play when the story reaches this node and the player loses replies and uploads, and the messages are never cleaned up.
It cannot test the game's tools
Dry run executes your logic against a stub, not against the real thing. A scan, an exploit or a conversation can still behave differently in the game.
It cannot save to the cloud
Everything lives in your browser and in files you download yourself. There is no account, no shared project and no history beyond undo.
It cannot recover a cleared project
New deletes every quest, website and conversation along with the autosaved copy, and it says so before it does it. Export or save first.
It cannot tell you the puzzle is solvable
No check can. The editor verifies that your quest is consistent, not that it is fair.

Which handbook version is this

This handbook documents editor build 2026-09-18.r196. The same stamp appears in the footer of every page, and the editor writes it into every mod it exports.

To check your editor
Open the canvas Debug panel. The build stamp is the first thing in it.
To check a mod you exported
Open dist/mod.js inside the .zip. The stamp is in the header comment. See the build stamp.
Why it matters
A handbook for an older build can describe a field that has since moved. If your stamp is newer than this one, the pages are probably still right, but the export window is the authority on what ships.
