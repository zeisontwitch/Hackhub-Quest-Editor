Wait

Flow control  flow.delay

What it does

Pauses the story here for as long as you set, then carries on.

When you'd use it

Use it to let two beats land in a sensible order: a message, then the reply to it.

Keep pauses short. The player waits through every one, and a long pause reads as a frozen game.

In the game, this looks like

Nothing happens for the length of the pause, then the next node runs.

Fields

Seconds

How long the story pauses here. Fractions are fine — 0.5 waits half a second.
Example
2
Default
1
Limits
0 or more. Steps of 0.5, so fractions that fine are allowed.
If you leave it empty
There is no pause. A blank value counts as zero and the story carries straight on.

Wires

SocketDirectionWhat to connect
Ininput Whatever should run immediately before this node.
Outoutput Whatever should happen after this node runs.

Then runs next When tests a condition Unlocks opens an objective Data carries a value

A wire only joins two sockets of the same colour, and the editor draws the wire in that colour. That is what the colours are for: match the colours and the connection takes, mismatch them and it will not.

Common mistakes

  • A long pause used to build tension. The player cannot tell a pause from a crash. Two or three seconds is plenty.

Messages you might see

  • Unreachable — nothing leads to this node, so the story never reaches the pause

Related nodes

  • Branch — Sends the story down one of two paths.
  • Timer — Fires the next node at a later in-game time — a delay, a clock time N in-game days from now, or a fixed in-game date.
  • Reroute — A tidy point for your wires.
  • Random pick — Picks one path at random.
  • Sequence — Fires several outputs in order.
  • Debug probe — Prints what is happening here.
