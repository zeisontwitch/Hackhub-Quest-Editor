HackHub Quest Editor — User Manual

Build a HackHub quest mod on a visual node canvas — no code. Wire up the story, drop in networks and files, write the conversations, then export a ready-to-play .zip the game can load.

34 node types 10 categories 13 templates 92 game events SDK 0.21.0 Runs in your browser

01 Introduction

What this tool is, and what it produces.

The Quest Editor is a browser app for authoring HackHub quest mods without writing TypeScript. You work on a node canvas: each node is one piece of the quest — an objective, a network, a phone call, a payout — and the wires between them describe the order things happen in. When you are done, the editor compiles that graph into a real mod and hands you a .zip the game loads.

There is no backend, no account, and no build step for you. The project lives in your browser's memory, a draft is kept in localStorage, and the export is a plain download. Nothing you make leaves your machine unless you save or export it yourself.

Who this is for. You do not need to program. You do need to know roughly how a HackHub quest plays — networks, tools, the terminal, the handbook — because the editor mirrors the game's own vocabulary rather than inventing its own.

02 Getting started

From an empty canvas to your first wired quest.

  • Open the editor. It loads to your last draft, or an empty project if this is your first visit.
  • Start from a template (recommended). Use New in the top bar and pick a starting point — or open the Templates gallery to load a fully worked example you can pull apart.
  • Add nodes. Drag a card from the palette onto the canvas, or press Shift+A to search for one at your pointer.
  • Wire them up. Drag from one node's output socket to another's input. Wires set the order of events.
  • Fill in the details. Select a node and edit its fields in the inspector on the right.
  • Check for issues. The status bar shows warnings and errors as you go.
  • Try it. Use Dry run to walk the quest as the game would run it.
  • Export. Use Export mod to download the .zip.

Palette

The node library. Cards are grouped by the ten categories, each with its own colour so the canvas stays readable. Drag a card to drop a node exactly where you let go, or click a card to add it at the centre of the view.

Canvas

The infinite work surface where the quest is built. Pan by dragging with the middle or right mouse button, and zoom with the scroll wheel. Nodes snap to a grid if you turn snapping on in Settings. A small toolbar on the canvas gives you quick toggles for animated wires, springy wires, arrange tools (Tidy up, Row, Column, Even across, Even down, Free), and the Debug panel.

Node search. Press Shift+A or right-click empty canvas to search for a node by name and drop it under the pointer. You can also drag a wire onto empty canvas and the editor offers to create a node that fits the wire.

Inspector

Select a node and its fields appear in the panel on the right. The fields are driven by the node type, so you only ever see what that node actually needs — text boxes, dropdowns, colour pickers, condition builders, device trees, and purpose-built editors for dialogue, databases, files and addon data. Some text fields carry a dice button to generate a plausible value and a sparkle button to insert a runtime tag (see Generate & tags).

Status & issues

The status bar reports the health of the project. The editor continuously runs graph and field checks and surfaces them as warnings (things worth a look) and errors (things that will stop a clean export). Fix errors before exporting; warnings are advice.

04 Building a quest

The shape of a working quest, start to finish.

  • Start the story. Every quest begins from the lifecycle nodes — Quest start runs once, and On start & reload runs each time the save loads (put your event listeners there so they survive a reload).
  • Give the player something to do. Add one or more Objective nodes. Each objective has an identifier, the line shown in the journal, an optional hint, extra info, and a suggested command.
  • Build the world. Add networks, Wi-Fi, firewalls, domains, databases and files so the player has something to hack.
  • React to the player. Use When event and Branch nodes to respond to what the player does — a port scan, a login, a downloaded file.
  • Talk to the player. Add Dialogue nodes for calls, chats and e-mails, and Notify for popups.
  • Pay out and move on. Reward with Pay the player, store progress with Set quest data, and chain into the next quest with Claim another quest.
  • End it. Complete the story from your last objective — see the note on the On quest complete node about why.
Order matters. Wires define sequence. If two effects must happen in a set order, wire them in that order (or use a Sequence node). Nodes with no incoming flow may never run.

06 Sockets & wires

How nodes connect, and what the different socket colours mean.

Each node has input sockets on the left and output sockets on the right. You wire an output to a compatible input by dragging between them. There are a few kinds of socket, and they only connect to their own kind:

Socket kindMeaning
FlowThe order of execution — In, Out, On complete, and the paired outputs like Correct/Wrong and Yes/No.
ConditionWhen / Trigger — connects an event or condition to the node that reacts to it.
UnlockUnlocks / Unlocked by — gates one objective behind another.
Fast wiring. Drop a wire on a node's body and the editor connects it to the matching socket automatically. Drop a wire on empty canvas to remove it, or onto empty canvas to create a node that fits. Double-click a wire to add a reroute point.

07 Dialogues

Writing the quest's conversations.

Open Dialogues from the top bar (or edit a Dialogue node in the inspector) to script what the player hears and reads. A dialogue can be a phone call, a Kisscord chat, an e-mail, or a WeeChat message — each with a simulated preview so you can see it the way the player will. You write lines, set who is speaking, and branch on the player's replies.

The from-address, handle, host and username fields carry the dice generator, so you can conjure a believable sender in one click and tune it from there.

08 Websites

In-game websites the player can browse.

Open Websites to build sites that live inside the game's browser. Each site has a host, a name, and one or more pages. For every page you set a path, a browser-tab title, a search-result description, and extra search words that help the in-game search find it; you can also mark a site as a popular site.

  • Edit pages visually, or Load HTML file to bring in your own markup.
  • Import pages folder to pull in a whole set of pages at once.
  • Duplicate or delete pages, and preview each one as it will appear.
The website builder's code view is pinned to a dark theme — its syntax colours are tuned for one background, like an embedded terminal.

09 Events & conditions

A When event node listens for one of the game's 92 events — a port scan, a login, a downloaded file, a bank transfer, and so on. Pick the event in the inspector; the editor knows each event's payload, so any conditions you add reference real fields. Events are organised into ten groups:

Conditions narrow when a trigger or branch acts. The inspector's condition builder lets you compare event fields and stored quest data without writing any code.

10 Generate & tags

Two small buttons that save a lot of typing.

  • Dice — generates a plausible hardcoded value for the field: a name, a company, an IP, a version number, an SSID, and so on. The generator is context-aware — for example, a Version field will match the service on the same node (an SSH service gets an OpenSSH/Dropbear version), and a last name will reuse the first name already on the node.
  • Sparkle — inserts a runtime tag like {{…}} that the game fills in when the quest runs (for example, the player's own name). Use the dice for a fixed value you decide now, and the sparkle for a value the game decides later.

11 Addons

Extending the editor with content from game mods.

Community game mods can add their own events and data shapes. Load them with Addons in the top bar; once loaded, their extra events show up in the event picker, and two Community nodes become useful: Give data to an addon (fill in a data shape the addon defines) and Addon node (drop a story node the addon provides). Addons you load are part of your project, so the export knows about them.

13 Dry run

Play the quest before you export it.

Dry run walks through the quest the way the exported mod would run it — following the wires, firing events, and showing the dialogue and effects in order. It is the quickest way to catch a broken wire, an objective that never completes, or a branch that always takes the wrong path. Use Run again to restart from the top after a change.

14 Exporting a mod

Turning the graph into a mod the game can load.

Export mod compiles the whole project into a ready-to-play mod folder — no coding needed — and downloads it as a .zip. Everything happens in your browser. Before it lets you download, the dialog shows a summary: the quests and websites in the mod, the addons it depends on, and any Needs attention (errors) or Good to know (warnings) items. Fix the errors, then press Download .zip.

The zip is a complete, unzip-and-play mod package. It contains:

FileWhat it is
manifest.jsonThe mod's identity for the game.
dist/mod.jsThe compiled, ready-to-run mod.
dist/manifest.jsonThe built manifest that ships alongside the code.
src/index.tsThe generated TypeScript source, if you want to read or rebuild it.
package.jsonDependencies, including the content SDK.
tsconfig.jsonTypeScript configuration.
esbuild.config.mjsThe build script that produces dist/mod.js.
README.mdA short readme for the mod.
Every export is stamped with the editor build number it was made with, so a mod and the editor that made it can always be matched up.

17 Saving your work

Where your project lives, and how to keep it safe.

  • Autosave draft. The editor keeps a working draft in your browser's localStorage, so a refresh won't lose your place. Press Ctrl+S to save the draft immediately.
  • Save to a file. Use Save in the top bar to write the whole project to a file you control, and Load to open it again. This is your real backup — the browser draft is convenience, not archive.
  • Export is not a save. The exported .zip is the compiled mod, not an editable project. Keep the saved project file if you want to edit later.
Clearing your browser data clears the draft. Save a project file before doing anything that might wipe localStorage.

18 Notes & limits

A few things worth knowing before you ship.

  • Ending a quest. With auto-complete off and no Complete button (the default), On quest complete never runs on its own — end the story from your last objective instead.
  • Wi-Fi. SDK 0.21.0 has no wireless networks, so Create Wi-Fi exports as an IP-reachable router network (see World building).
  • Preferences don't travel. Theme, font, grid and wire settings are yours alone — they are never part of an exported mod.
  • Everything is local. No account, no server, no upload. Your project stays in your browser until you save or export it.
  • Build stamping. Each export records the editor build it was made with, which must match the build the mod expects at load time.
