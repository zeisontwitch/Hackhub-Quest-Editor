Tool response

World building  world.toolResponse

What it does

Overrides what one of the game's tools prints, so a scan or a lookup answers with what your story needs.

When you'd use it

Use it when the player runs a real command and the answer has to be one you wrote: the scan that reveals the target, the lookup that names its owner.

Key it to what the player types. A response that answers every input hands them the target on their first random try.

In the game, this looks like

The player runs the command and reads your response instead of the game's own.

A wire only joins two sockets of the same colour, and the editor draws the wire in that colour. That is what the colours are for: match the colours and the connection takes, mismatch them and it will not.

Common mistakes

  • The response answers anything. Key it to a specific input, or the player's first careless scan gives them the answer.
  • The response is left running. Leave Remove when the quest ends on, or the command keeps answering with your text in every later quest.

Messages you might see

  • Unreachable — nothing leads to this node, so the response is never registered

Related nodes

  • Create network — Builds the machines the player breaks into.
  • Create Wi-Fi — Creates a wireless target the player can crack and join.
  • Firewall rule — Allows or blocks a port.
  • Change port — Opens, closes, adds or removes a port.
  • Register domain — Points a hostname at an address.
  • Create database — Data for the player to dig out.
  • Place files — Drops files on a machine.
