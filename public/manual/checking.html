Checking your quest

Every message the editor can show you, quoted exactly as it writes it. Paste the wording into the search box to find the one you are looking at.

The editor reads your quest as you build it and tells you what looks wrong. Nothing here is a guess on your part: if the editor is quiet, the shapes it checks are sound. If it is not, this page has the message you are seeing and what to do about it.

Messages fall into two groups. The first group watches the shape of your quest while you edit — a node nothing points at, an objective that can never finish. The second group only appears when you export, because it needs the whole mod in front of it: two websites fighting over one domain, a machine with a login and no accounts.

Where messages appear

On the node
A small badge on the card, visible from across the canvas. This is how you find a problem in a quest too big to read node by node.
In the inspector
Under the field the message is about, when you have that node selected. Field messages only show while the node is selected, so they cannot nag at you from the other side of the canvas.
In the status bar
A running count of what is wrong, and the message for whichever node you last touched.
In the export report
Everything the export checks found, listed before the .zip is written. See the report.

What the two colours mean

Amber
Unfinished, or fragile. Exporting still works, and the player may never notice. Fix it before you ship, but nothing is broken right now.
Red
The player will hit this. Either the quest cannot be finished, or something you built will not survive the trip into the game. Fix it before you export.

There is no third level. A quest with no messages has nothing the editor can find fault with, which is not the same as a quest that plays well — only playing it tells you that. See Dry run for the closest thing to a test drive.

Every message

Each entry below quotes the editor's own wording. The exact text is what the search box matches, so copy it from the status bar rather than paraphrasing it.

Unreachable

Nothing leads to this node. Wire it to the chain that should run it — nodes do nothing until something points at them.
Colour
Amber
Where
On the node, and in the status bar.
What it means
The node is on the canvas and is never run. A node only does something when another node points at it, or when it is one of the lifecycle nodes that starts a chain by itself.
What to do
Drag a wire from the node that should run it into this node's input. That is usually the last node of your Quest start chain. If the node is left over from an idea you dropped, delete it instead.

No trigger

Nothing completes this objective. Wire a “When event” node into its trigger socket, or the player can never finish the quest.
Colour
Red
Where
On the objective, and in the status bar.
What it means
The player receives the objective and can never tick it over. There is no condition attached to it, so nothing in the game can complete it. A quest with an objective like this cannot be finished.
What to do
Add a When event node, pick the game event that means the player did the thing, and wire its When socket into the objective's Trigger socket.

Dead end

The “…” outcome goes nowhere, so the quest stalls if the player takes it.
Colour
Amber
Where
On the node, and in the status bar.
What it means
The node offers more than one way out and at least one of them is unwired. The wording names the outcome, so Yes or No tells you which side is missing. The editor writes a different version for two node types, because the same shape means something different in each.
On a Sequence
It reads The "…" output goes nowhere, so that step of the sequence does nothing. A step with no wire is a beat that never lands.
On Manual input
It reads The "…" outcome goes nowhere, so a wrong answer shows the failure message and the player tries again. That is the usual design for a passphrase, so this one is often correct as it stands.
What to do
Wire the named outcome to the node that should run down that path, or remove the outcome if the path should not exist. On a Manual input, leaving it unwired is fine when retrying is the design.

Only runs on completion

This is wired, but it only runs if the quest completes — with auto-complete off and no Complete button (the default) that never happens. End the story from the last objective's “done” instead.
Colour
Amber
Where
On the node, and in the status bar.
What it means
You have built the ending of your quest on On quest complete. Under the default settings a quest never reaches that state, so everything you wired behind it never runs. The player finishes the last objective and sees nothing.
What to do
Move those nodes onto the last objective's On complete socket. That path runs when the objective ticks over, which is the moment you actually mean. If you really want completion, turn it on in the quest's behaviour settings instead.

Empty

Nothing is wired to “…” That is fine if you do not need it — delete the node to clear this.
Colour
Amber
Where
On the node, and in the status bar.
What it means
One of the four lifecycle nodes is on the canvas with nothing after it, so it runs and changes nothing. The message names the node in the quotes.
What to do
Wire the nodes that should run at that moment to its output. On Quest start that is usually your briefing message first. If you do not need the node, delete it and the message goes with it.

No machine set

No machine set — this node does nothing until it points at one.
Colour
Amber
Where
In the inspector, under Device IP or Protected IP.
What it means
A Change port or Firewall rule node has no machine to act on. The field is blank, which usually means you have not got to it yet rather than that something is broken.
What to do
Type the target address token to aim it at the machine your network created, or pick Random — the quest's network on a firewall rule.

No network creates that machine

This is set to a machine, but no network in this quest creates one for it to act on.
Colour
Amber
Where
In the inspector, under the address field.
What it means
The address is filled in, and nothing in the quest brings a machine with that address into the world. The node points at a machine that will not exist.
What to do
Add a Create network node from World building and point this at a device in it. If you do not need the node, remove it.

Files aimed at a network that does not exist

This “Place files” node puts files on a remote device, but no network in this quest exists for that device to live on — export would drop the files.
Colour
Red
Where
In the inspector, under Device IP.
What it means
The files have nowhere to land. Exporting drops them rather than failing, so the player gets a quest with the clue missing and no error anywhere.
What to do
Add a Create network node and give it the device this node is aimed at.

Files aimed at an address nothing uses

No device in this quest uses that address, so these files would be dropped when you export.
Colour
Red
Where
In the inspector, under Device IP.
What it means
The address is typed in and matches no device your network creates. With no address at all, the editor writes No address set, so the files have nowhere to land instead. Either way, export drops the files.
What to do
The message lists the addresses your quest does create. Point this node at one of them, or at the same token you gave the network.

Files aimed at a device with no account

That device has no user account, and files mount under a user's home folder — export would drop the files.
Colour
Red
Where
In the inspector, under Device IP.
What it means
The device exists, but there is nobody logged into it, and files land in a user's home folder. Export drops them.
What to do
Add a user account to that device in your Create network node.

The report before you export

Exporting runs a second set of checks that need the whole mod in front of them: what your websites do to each other, whether a machine can actually be broken into. The report lists everything it found before the .zip is written, so you can go back and fix it.

Red entries mean the export dropped or changed something. Amber entries mean it shipped what you built, and what you built is probably not what you meant.

A network the game cannot build

… has machines behind it, but only a router or a splitter can hold other machines.
Colour
Red
What it means
You have hung a device behind something that cannot host one. The game has no way to build the shape.
What to do
Put a router or a splitter between them in your Create network node.

Two more red entries come from the same place. One names a machine carrying firewall rules when only a firewall device enforces them, so the rules are ignored. The other names a machine with a login service open and no user accounts, so the player cannot break in — there is nothing to log in as.

A version a tool will not read

… metasploit needs three numbers (for example “OpenSSH 7.2.0”) — it rejects anything else.
Colour
Red
What it means
A vulnerability's version is written in a form the game's attack tool refuses to read, so the player cannot exploit it. The weakness is on the list and does nothing.
What to do
Write the version as three numbers, the way the tool expects.

Two websites on one domain

… is the host of … websites in this mod. Domains are global — two sites on one host will fight over it.
Colour
Red
What it means
Domains belong to the whole game, not to your quest. Two sites claiming one host means whichever loads last wins, and the other disappears.
What to do
Give one of them its own hostname. Two related sites read better as subdomains of one host anyway.

Three more entries come from the same checks. A red one names a host with two pages at the same path, which ship as two definitions of one address. Another names a page whose path does not start at the host root. An amber one warns that a placeholder domain ships as a real site any player can find, and another mod may already be using it.

A conversation nobody reaches

… a conversation is set to “play when the story reaches this node” but nothing is wired into it — it never plays.
Colour
Amber
What it means
A Dialogue node waits for the story to arrive and the story never does. The player never has the conversation.
What to do
Wire the node into the chain, or set the conversation to start some other way.

An addon node that is not set up

… a “Give data to an addon” node is not set up yet.
Colour
Amber
What it means
A node that depends on a community addon has no pack or node chosen, so it exports as something that does nothing. The same check covers Addon node.
What to do
Open the node and pick the pack and the shape or node it should use. If the addon is not installed, install it first.

An upload that becomes a message

… Kisscord uploads compile to a “[uploaded file …]” message.
Colour
Amber
What it means
A file attached to a Kisscord conversation does not reach the player as a file. It arrives as a line of text standing in for it. Nothing is lost; the player does not get the attachment itself.
What to do
Nothing, if a line of text is enough. If the player needs the actual file, put it somewhere with Place files and have the conversation point at it.
